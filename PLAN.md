# ValheimGreek — план плагина

Клиентский мод только на лут. Рубка, бой, крафт, строительство, двери, еда, сон и прочие действия не патчатся и работают как в ваниле.

Три изменения:

1. Автолут выключен: выброшенные предметы остаются на земле.
2. Подбор по клавише взаимодействия открывает выбор слова. На экране русский prompt случайной карточки из Greek3 (например «Идти») и 4 греческих варианта. Слово с предметом не связано.
3. У каждого лежащего предмета свой счётчик ошибок. Первая попытка требует 1 верный ответ. Каждый неверный ответ увеличивает счётчик, и следующая попытка требует уже на один верный ответ больше.

Стек: .NET Standard 2.0, C# 9, BepInEx 5.4, HarmonyX, Unity IMGUI, Mono-сборка `assembly_valheim.dll`.

## Решения MVP

| Тема | Решение |
|------|---------|
| Объём | Только лут на земле: `ItemDrop`. |
| Автолут | Префикс `Player.AutoPickup` возвращает `false`. Предметы лежат, пока игрок сам не нажмёт взаимодействие. |
| Подбор | Префикс `ItemDrop.Interact`. Предмет забирается, когда в этой попытке набрано нужное число верных ответов подряд. Тогда replay вызывает тот же `Interact`. |
| Счётчик предмета | Целое `misses` на ZDO лежащего `ItemDrop`. Ключ `valheimgreek_misses`, по умолчанию 0. Число верных ответов за попытку = `misses + 1`. |
| Неверный ответ | Текущая попытка кончается, частичный прогресс сбрасывается, предмет остаётся, `misses` становится на 1 больше. Следующее взаимодействие требует уже `misses + 1` верных. |
| Верный ответ внутри попытки | Если набрано меньше, чем `misses + 1`, сразу следующий случайный вопрос. Предмет ещё на земле. |
| Слово | Случайная карточка из всего экспорта Greek3 на каждый вопрос. Привязки к типу предмета нет. |
| UI | Русский prompt, 4 кнопки и строка прогресса `1/3`. Одна кнопка — греческая лемма карточки, три — леммы других карточек. Порядок перемешан. |
| Escape | Окно закрывается, предмет остаётся, `misses` не меняется, прогресс этой попытки сгорает. |
| Чей ввод | Только `Player.m_localPlayer`. |
| Ошибка патча | Fail-open: исключение логируется, оригинальный метод выполняется. |
| Могила | `TombStone` не патчится. Свой лут после смерти подбирается как в ваниле. |
| Ягоды, кремень, ветки | `Pickable` не патчится. Это не `ItemDrop` и не автолут. |

Счётчик живёт на предмете, а не на игроке. Соседняя куча древесины со своим `misses` не наследует чужие ошибки. Успешный подбор предмет забирает, так что хранить «уже выучено» не нужно.

## Поток

```
игрок идёт по предмету
    → Player.AutoPickup не выполняется
    → предмет лежит, misses на ZDO (нет ключа = 0)

игрок жмёт взаимодействие по ItemDrop
    → Prefix ItemDrop.Interact
    → не локальный игрок / окно уже открыто / чат / меню → как описано ниже
    → иначе return false, курсор свободен, TakeInput = false
    → нужно верных: misses + 1, сейчас 0
    → случайное слово, 4 варианта
    → верный, и счётчик попытки ещё не добран: новое слово, прогресс + 1
    → верный, и добрано misses + 1: Bypass + повтор Interact
    → неверный: misses += 1 на ZDO, окно закрыто, предмет на месте
    → Escape: окно закрыто, misses тот же, предмет на месте
```

Пример. Новая древесина: `misses = 0`, нужен 1 верный. Ошибка → `misses = 1`. Следующая попытка: два верных подряд. Ошибка на втором → `misses = 2`, оба ответа этой попытки не засчитаны. Следующая попытка: три верных подряд.

Повтор нельзя сделать в том же кадре Prefix: игрок отвечает после возврата из хука. Префикс сохраняет `PendingAction` со ссылкой на `ItemDrop`, флаг `hold` и флаг `alt`. После успеха `Bypass` вызывает `__instance.Interact(localPlayer, hold, alt)`. Второй заход в патч при `Bypass` выполняет оригинальный метод.

Если к моменту ответа объект уничтожен (`== null`) или его уже забрал другой игрок, replay не вызывается, в лог пишется причина.

Пока окно открыто, другой `ItemDrop.Interact` локального игрока возвращает `false` и не подменяет текущий предмет и его прогресс.

`misses` пишется в ZDO предмета (`ZNetView.GetZDO()`), чтобы куча помнила долг после того, как игрок отошёл и объект выгрузился вместе с зоной. Перед записью, если вид не у локального владельца, вызывается `ClaimOwnership` — обычный путь для лежащего дропа, с которым взаимодействует локальный игрок. Нет ZDO — счётчик держится на компоненте этого `GameObject` до уничтожения объекта. Чужие клиенты читают тот же ZDO, так что долг кучи общий для мира.

## Что патчим и зачем

Сигнатуры сверяются с локальным `assembly_valheim.dll` до кода. Ожидаемые методы ванильного Mono-билда:

| Класс и метод | Роль |
|---------------|------|
| `Player.AutoPickup(float dt)` | Единственная точка автоподбора. Префикс всегда возвращает `false`, когда `DisableAutoPickup` включён (по умолчанию да). Предметы с `m_autoPickup` перестают прыгать в инвентарь от близости. |
| `ItemDrop.Interact(Humanoid character, bool repeat, bool alt)` | Ручной подбор. В этой сборке второй аргумент называется `repeat`: удержание клавиши приходит с `repeat = true` и ванильный метод сразу выходит. Диалог открывается только на первый вызов. |
| `Player.TakeInput` | Пока диалог открыт, префикс возвращает `false`. |
| `GameCamera.UpdateMouseCapture` | Пока диалог открыт, префикс возвращает `false`, затем `Cursor.lockState = None` и `Cursor.visible = true`. Иначе камера снова спрячет курсор в том же кадре. |
| `ItemDrop.GetHoverText` | Postfix дописывает к подсказке число верных, которое нужно сейчас: `misses + 1`. Игрок видит долг кучи до нажатия. |

`ItemDrop.Pickup` отдельно не блокируется. Автолут ходит в него из `Player.AutoPickup`; ручной подбор ходит в него из `Interact`. Перекрыты оба входа.

Условия префикса `Interact`:

- `Config.Enabled`.
- `user` — `Player.m_localPlayer`. Чужой подбор на этом клиенте идёт в оригинальный метод.
- Игрок не в чате (`Chat`), консоли (`Console`), меню (`Menu`) и игровом `TextInput`. В этих UI оригинальный метод тоже не перехватывается.
- Словарь загружен и в нём есть хотя бы 4 карточки с различимыми леммами. Иначе fail-open и подбор как в ваниле.
- Тело префикса в `try/catch`. Исключение → `return true`.

## Диалог

IMGUI по центру экрана.

- Строка долга: сколько верных уже есть в этой попытке и сколько нужно (`1/3`).
- Строка prompt: первый русский перевод карточки до `/` («Идти»).
- Четыре кнопки с греческой леммой. Клик мышью или клавиши `1`–`4`.
- Подсказка: Esc оставляет предмет и не увеличивает счётчик.
- Поле ввода текста нет.

Неверный вариант закрывает окно. Следующее взаимодействие начинает попытку с нуля уже с новым `misses + 1`.

Верный индекс сравнивается с нажатой кнопкой. Текстовая нормализация нужна при сборке четвёрки, чтобы три лишних варианта не совпали с верным после снятия ударений.

Шрифт Valheim греческий не рисует. На старте плагин берёт системный шрифт с греческими глифами (`Font.CreateDynamicFontFromOSFont`: Arial, Noto Sans или первый подходящий из списка ОС) и ставит его на своё окно.

Закрытие диалога в том же кадре возвращает мышь игре.

## Словарь

Источник — `../Greek3/words/**/*.md`. Игра читает собранный `dictionary.json` рядом с DLL и Markdown не парсит.

Парсер экспортера повторяет `Greek3/src/build/parse-word.ts`:

- slug = путь от `words/` без `.md` (`verbs/иду πάω`);
- `translation` — текст до `:`, варианты через `/`;
- `baseForms` — греческие формы после `:`, разделитель ` - `;
- секция «Формы» — пары `греческий - русский`.

В экспорт не входят `readme.md`, `songs/`, `lessons/`, `blocks/`, `essays/`.

Рантайм-запись:

```json
{
  "id": "verbs/иду πάω",
  "prompt": "иду",
  "target": "πάω"
}
```

- `prompt` — первый русский вариант до `/`.
- `target` — лемма: форма из «База» без артикля (`ο η το οι τα τον την τους τις στον στην στο`), не прошедшее и не форма с `θα`. Если такая форма не выделяется, берётся первая форма «База».

Пример четвёрки для «Идти» / «иду»: кнопки `πάω`, `τρώω`, `πίνω`, `βλέπω` в случайном порядке. Верная одна.

Сборка вопроса (чистая функция в Core, без Unity):

1. Перемешать карточки, у которых `prompt` и `target` не пустые.
2. Взять первую как вопрос.
3. Добирать другие карточки, пока не наберётся 3 отвлекающих. После нормализации их `target` не равен верному и не повторяет уже взятые.
4. Перемешать 4 кнопки, запомнить индекс верной.
5. Если отвлекающих меньше трёх — вопрос не создаётся, подбор fail-open.

Отдельного `progress.json` нет. Долг хранится на ZDO конкретной кучи.

### Нормализация

Для сравнения лемм между собой:

1. `Trim`, схлопнуть пробелы, `ToLowerInvariant`.
2. `Normalize(NormalizationForm.FormD)` и убрать `NonSpacingMark`.
3. Конечная сигма: `ς` → `σ`.

### csproj плагина

- `TargetFramework` плагина: `netstandard2.1`. Сборка Valheim ссылается на `netstandard` 2.1, с `netstandard2.0` проект не компилируется. Core остаётся на `netstandard2.0`.
- `LangVersion`: `9.0`
- `Nullable`: enable
- `record` не используется.
- Ссылки с `Private=false`:
  - `$(BepInExDir)/core/BepInEx.dll`
  - `$(BepInExDir)/core/0Harmony.dll`

  - `UnityEngine.CoreModule.dll`, `UnityEngine.IMGUIModule.dll`, `UnityEngine.InputLegacyModule.dll`, `UnityEngine.TextRenderingModule.dll` из `$(ManagedDir)`
- Если префикс не компилируется из-за непубличных методов, ссылка на publicized `assembly_valheim` из BepInExPack (`PublicizedDir`).

Локальные пути к Steam — в `Directory.Build.props` (в `.gitignore`). В репозитории только `Directory.Build.props.example`:

- macOS: `~/Library/Application Support/Steam/steamapps/common/Valheim/valheim.app`, Managed — `Contents/Resources/Data/Managed`, BepInEx — корень установки игры.

## Краши, которых избегаем

- Префикс не трогает `ZNet` и не шлёт RPC.
- `Interact` чужого игрока не блокируется.
- Пустой словарь, меньше 4 разных лемм, открытые чат или меню — оригинальный подбор.
- Replay проверяет, что `ItemDrop` ещё существует.
- Открытый диалог не заменяется новым предметом.
- Escape не вызывает replay и не меняет `misses`.
- Запись `misses` идёт в ZDO только после неверного ответа. Верные ответы до конца попытки в ZDO не пишутся.
- Повторный `ClaimOwnership` на уже принадлежащем игроку объекте не делается.
- `Enabled = false` снимает оба патча по смыслу: префиксы сразу выходят в оригинальный метод.

## Проверка

Автотесты Core:

- `verbs/иду πάω`: prompt начинается с русского «иду», target `πάω`;
- `QuizBuilder` даёт 4 варианта, ровно один совпадает с target после нормализации, дублей нет;
- на пуле короче 4 различимых лемм билдер возвращает отказ;
- `readme.md` и `songs/` в JSON не попадают;
- `δέΝτρο` и `δεντρο` нормализуются одинаково.

В игре:

1. Срубленное дерево роняет древесину на землю. В инвентарь само ничего не прилетает. Рядом с монетой, камнем, смолой — то же.
2. Взаимодействие с лежащим предметом открывает «Идти»-подобный экран: русский prompt и 4 греческие кнопки. WASD не двигает персонажа, курсор виден.
3. У новой кучи подсказка показывает 1 верный. Одна верная кнопка или её цифра забирает именно этот предмет.
4. Неверная кнопка закрывает окно, предмет лежит. Подсказка той же кучи показывает 2. Следующая попытка забирает предмет только после двух верных подряд. Ошибка на втором снова закрывает окно, подсказка становится 3, засчитанный первый ответ не переносится.
5. Escape на попытке из двух вопросов оставляет прежнее число на подсказке. Прогресс этой попытки сгорает.
6. Удар по дереву, двери, костёр, еда, атака моба, установка постройки — без окна.
7. Сундук и надгробие открываются как в ваниле.
8. `Enabled = false` возвращает автолут.

## Порядок реализации

1. Core: парсер, нормализатор, `QuizBuilder`, тесты на файлах Greek3.
2. Экспортер всего словаря в `dictionary.json`.
3. csproj, example props, PostBuild.
4. Каркас плагина, конфиг, загрузка JSON.
5. IMGUI на 4 кнопки и захват ввода. Временная кнопка открывает случайный вопрос без подбора.
6. `Player.AutoPickup` и проверка, что дроп остаётся на земле.
7. `ItemDrop.Interact`, счётчик на ZDO и replay. Удалить временную кнопку.
8. Чеклист из раздела «Проверка».
